# 项目架构

## 组成

“哎一把”由一个 Vinext 网页服务和一个 Node.js WebSocket 多人服务组成。

- 网页服务负责页面、静态资源、多人入口和健康检查；单人玩法所需题库随页面资源发布。
- 多人服务负责大厅、房间、重连、倒计时、答案校验和胜负结算。
- 浏览器负责界面、搜索候选和本机战绩，不作为胜负或答案的权威来源。

## 单人玩法

经典推理、线索阶梯和时光机在页面加载后使用浏览器本地状态机。题库、抽题袋、答案、操作记录和结算状态都
保存在当前页面内存，并按版本写入 localStorage 以便刷新恢复；猜测、跳过、放置、投降和再来一局不请求单人
服务端。完整题库随页面资源加载，因此单人答案可以被用户通过开发者工具查看，本机战绩也不具备可信竞赛属性。

旧版 `/api/singleplayer`、`/api/clues` 和 `/api/timeline` 仅在过渡期返回 410，提示刷新页面完成热更新；新版
页面不会调用这些接口。

## 多人玩法

浏览器通过 /pk/ws 连接多人服务。公开大厅只展示可加入房间的摘要；房间状态、答案和阶段计时只保存在服务
内存中。房主退出会解散房间，服务重启后房间不会保留。

多人服务支持经典推理和线索阶梯。线索阶梯由服务端统一推进层数，所有玩家在同一层完成操作或阶段超时后
才进入下一层。

## 题库文件

- 完整题库和搜索索引都随页面构建发布；浏览器使用完整作品信息完成单人判定。
- 搜索索引仍只包含作品名、别名、拼音和稳定标识，减少搜索计算和页面初始开销。
- 标准题库与扩展题库分开生成，但共用相同字段和判定规则。

## 本机数据

localStorage 保存本机战绩、抽题历史和单人回合状态。多人重连凭据仍由多人服务下发并按其协议保存；项目没有
账号系统，也不会把本机战绩视为服务端权威数据。
