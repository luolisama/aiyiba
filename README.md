# 哎一把

“哎一把”是一个以 ilem 音乐作品为题库的中文猜歌网页。玩家可以根据演唱、引擎、投稿日期、歌名字数和播放等级等线索逐步锁定作品，也可以和朋友在同一房间竞速作答。

**在线游玩：** [aiyiba.getuphole.top](https://aiyiba.getuphole.top)

**项目状态：** 持续维护 · Node.js 22+ · AGPL-3.0-only

[查看玩法](#玩法) · [本地运行](#本地运行) · [参与贡献](#参与贡献)

## 玩法

### 经典推理

比较每次猜测与答案的六项信息，通过颜色与箭头逐步缩小范围。普通模式有 6 次机会，困难模式有 4 次机会。

### 多人模式

支持 2–8 人创建公开或房间码房间。房主可以选择标准/扩展题库，以及经典推理或线索阶梯玩法；答案、阶段时间和胜负均由服务端统一判定。

### 线索阶梯

从引擎开始逐层揭示线索。猜错或跳过后会进入下一层，最多依次公开播放等级、演唱、投稿年份和歌名字数，最后一次使用已有线索完成作答。

### 时光机

把 10 首隐藏投稿日期的作品依次插入时间线。每次放置后立即揭晓真实日期，最终按正确位置和相邻关系结算成绩。

## 题库

- **标准题库：** 收录 ilem Bilibili 主账号中的 70 首音乐作品。
- **扩展题库：** 共 81 首，在标准题库基础上补充 ilem/onyk 作为 staff 参与的原创作品和被删除的作品，不包含翻唱与 Remix。
- 播放量为定期更新的数字快照，不代表实时播放量。
- 题库包含标题、BV 号、投稿日期、演唱、引擎和播放等级；部分字段经过人工核对和校正。

完整来源和收录口径见 [数据来源与收录规则](docs/data-sources.md)，玩法判定见 [游戏规则](docs/game-rules.md)。

## 工作方式

- React 19、TypeScript、Vinext 和 Vite 负责网页界面与服务端路由。
- 经典推理、线索阶梯和时光机在页面加载后均由浏览器本地抽题、判定、存档和结算；单人战绩只保存在本机，不是可信竞赛成绩。
- 多人模式通过 WebSocket 同步房间状态，由独立服务保管答案、重连凭据和胜负结果。
- 浏览器会随页面资源加载完整题库，因此用户可以通过开发者工具查看单人答案；这是无排行、无服务端单人计分前提下的明确取舍。
- 题库随应用构建发布，搜索索引和判定数据都在浏览器本地使用，不建立用户账户。

更多说明见 [项目架构](docs/architecture.md) 和 [答案与安全边界](docs/security-model.md)。

## 本地运行

需要 Node.js 22.13 或更高版本。

```powershell
git clone https://github.com/luolisama/aiyiba.git
cd aiyiba
npm install
npm run dev
```

多人模式需要另开一个终端：

```powershell
npm run pk:server
```

网页默认运行在 `http://127.0.0.1:3000`，多人服务默认监听 `127.0.0.1:3001`。生产环境请复制 `.env.example`，设置自己的 `SITE_ORIGIN` 和多人允许来源。

## 检查与测试

```powershell
npm run typecheck
npm run lint
npm test
```

浏览器回归测试会自动启动并清理本地网页与多人服务：

```powershell
npm run test:e2e
```

日常 CI 运行类型检查、Lint、构建和核心逻辑测试；浏览器 E2E 由维护者在发版前手动触发。

如果本地文件监听环境不支持文件系统事件，可在启动前设置 `USE_POLLING=1`（或 `true`）启用轮询。

## 自行部署

生产环境需要同时运行网页服务和多人 WebSocket 服务，并将 `/pk/ws` 反向代理到多人服务。仓库提供不含真实服务器信息的 Nginx 与 systemd 示例。

详细步骤见 [自部署说明](docs/self-hosting.md)。仓库不会保存正式站点的服务器地址、SSH 配置、证书或发布凭据。
